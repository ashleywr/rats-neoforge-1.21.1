# Rat AI regression tests

Run `./gradlew runGameTestServer` with Java 21. Cached dependencies can use `--offline`.
The server creates its disposable world under `build/gametest`; it does not open a client or a saved gameplay world.

Tests run actual Rats entities and Minecraft navigation in NeoForge 1.21.1. They cover crop removal, unreachable crops, interrupted routes, speed upgrades with held berries and no deposit chest, multiple berry bushes, navigator retention and cage exit, renamed stat upgrades, competing movement during cheese pickup, pickup interruption, displaced cheese, and Gather delivery to a chest. Flight tests check airborne harvest and pickup, destination changes, path failure, cancellation of flight acceleration, and delivery. Farmer tests check inaccessible soil, planting, bonemeal, and failed-route recovery. Transport tests check removed chests and energy/fluid continuation; Follow checks navigator replacement.

Some tests drive a goal directly to inspect a specific lifecycle transition; travel and chest delivery tests tick the entity's normal AI. The synthetic low-priority movement goal makes the former conflict between the target selector and goal selector deterministic.

`ai_arena.nbt` is an empty 16 × 6 × 16 structure with no entities. Each test builds a floor and lights the arena so crop survival does not depend on terrain or sky lighting. This source set is available in development runs and is excluded from the release JAR.

`WildRatGameTests` adds ten cases for visible and obstructed food chests, normal chest/crop theft, carrot loot, an enclosed crop with nearby cheese, cats interrupting raids, baited traps, and disabled raiding settings or `mobGriefing`. The empty `wild_ai_arena.nbt` is 80 × 6 × 80 with a centered 48-block lit floor. The margin separates actors from neighboring targets beyond the 32-block food search. Cheese pickup requires the tested rat to hold the cheese. Cat avoidance gets several scheduler updates before its deadline. Crop raids explicitly reset the normal 1,200-tick initial cooldown where a raid is expected. Configuration checks restore all changed values synchronously in `finally` blocks.

`RatPortGameTests` adds six cases for clientbound fluid and thrown-block registration, filled and empty fluid encoding, Ratlantis sword attributes, Chef output conservation, and server disenchanting. These server tests do not establish client particle or item-mutation behavior; those require a client run.

`RatSpawnGameTests` adds eight cases for the configurable garbage-rat lighting policies. `DARK` retains the original daylight/torch restrictions; `NIGHT` allows lit heaps at night; `ANY` allows lit heaps during daytime too. Direct calls use real blocks and entities, force the chance roll, assert fixture lighting, and restore shared time/config/gamerules synchronously. They also check spawning gamerules, obstruction, unchanged natural-spawn lighting and passive-mode behavior, and retained Pied Garbage restrictions. These tests establish lighting policy, not natural random-tick arrival rates or a live village's population.

`RatLootGameTests` adds four cases for loaded loot tables. Fixed-seed normal loot rolls must produce Plastic Waste and reusable piles, Fortune III must always produce one Plastic Waste, and Silk Touch must preserve the pile (including when commands combine it with Fortune). The CTOV case opens 32 pet-shop chests using CTOV's saved Domestication Innovation table ID, including an actual template seed, and requires nonempty contents without Domestication Innovation installed. The fallback delegates to Rats' pet-shop loot and is disabled when Domestication Innovation is loaded. The tests run the normal NeoForge loot pipeline with its real registries and global loot modifiers. They do not establish full-pack compatibility or assert an exact sampled drop rate.

`RatGameTestSetup` registers the 55 normal cases through NeoForge's `RegisterGameTestsEvent`. Optional JVM properties `mctest.filter` (case-insensitive method or `Class.method` glob with `*`) and `mctest.report` (JSONL destination) enable targeted execution and failure snapshots without changing gameplay sources. Explicit template namespaces replace automatic `GameTestHolder` scanning so filtering cannot be bypassed by a second registration pass. Plain Gradle runs still register every normal case. The reserved `__reporter_self_check__` filter registers one intentional failure only; it is excluded from the normal suite.
